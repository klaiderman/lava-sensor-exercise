# IMPL_BVB — implementation-level build-vs-buy

Verdicts: **REUSE** (take the dependency) · **STEAL_PATTERN** (copy the shape, write the code) · **BUILD** (write it, no prior art needed) · **REJECT** (evaluated and refused).

| # | Subsystem | Verdict | Evidence | Reversal condition |
|---|---|---|---|---|
| 1 | **procfs / sysfs parsing** | **BUILD** (with STEAL_PATTERN from `prometheus/procfs` for field naming) | The sensor reads roughly a dozen well-known files (`meminfo`, `cpuinfo`, `os-release`, `sys/block/*`, `sys/class/dmi/id/*`). `os.ReadFile` already handles size-0 pseudofiles correctly (R5-F19) but is unbounded, so we need our own capped reader regardless (R5-F20); once that exists, the parsing is `strings.Cut` per line. Taking `prometheus/procfs` would import a large surface to save ~150 LOC and would still not give the bounded/mode-gated read semantics we require (R5-F18, R5-F24). | If the check set grows to need scheduler/netstat/cgroup-v2 parsing, reconsider `prometheus/procfs` for those specific parsers only. |
| 2 | **DMI reading** | **BUILD**, patterned on ghw | ghw's `linuxdmi.Item()` is 8 lines: read the sysfs file, on error log and return the `"unknown"` sentinel (R5-F6). We need a strictly better version anyway — carrying the path and errno as evidence rather than a bare sentinel — and importing ghw would bring the `GHW_CHROOT` production override into a security sensor (R5-F5). | None foreseeable. DMI reading is a dozen file reads. |
| 3 | **Block-device enumeration** | **BUILD**, patterned on ghw `pkg/block` | Enumeration is `ReadDir("/sys/block")` + per-device attribute reads, with the wrinkle that 28/28 entries are symlinks and must be traversed (R5-F21) — handled by `os.Root("/sys")`, which follows in-root symlinks and blocks escapes (R5-F22). ghw's block package additionally shells out and models partitions we do not need. `lsblk --json` exists on the host but adds a subprocess, a JSON contract and a version dependency where a sysfs read suffices. | If partition/holder/dm topology becomes a graded requirement, re-evaluate ghw `pkg/block` for that subtree specifically. |
| 4 | **JSON-schema validation** | **REUSE — `github.com/santhosh-tekuri/jsonschema/v6`** | Independent Bowtie conformance (raw 2026-09-08 run, pass rates recomputed): 1301/1301 on 2020-12, 1261/1261 on 2019-09, 929/929 on draft-07, versus xeipuuv at 874/929 on draft-07 with 20 hard errors and no modern-dialect registration (R5-F52). Only these two Go libraries have harnesses at all; kaptinlin and qri-io claims are self-reported (R5-F53). One production dependency (`golang.org/x/text`), released 2026-08-06, 15 open issues (R5-F54). Writing a 2020-12 validator ourselves is a multi-thousand-line project — the one place in this build where buying is unambiguously right. | Real schema needs draft-03/04, or trips a santhosh `$dynamicRef` issue → fall back to kaptinlin *after* running the official test suite ourselves. |
| 4b | *(alternative)* schema→Go codegen (`omissis/go-jsonschema`) | **REJECT as the strategy, optional as an addition** | Codegen fixes the schema at compile time; the schema is a customer artifact and is not yet in hand (R5-F55, R5-F51). It cannot validate the produced document, which is what "must validate against finding.schema.json" requires. | Once the real schema arrives, generating types alongside runtime validation is a cheap compile-time drift check. |
| 5 | **POSIX ACL reading** | **BUILD** (~50 LOC over stdlib) | `getfacl` is absent on the target, so shelling out is not an option there at all. `syscall.Getxattr` is in stdlib on linux and was exercised in LOCAL_REPRO (R5-F26); the wire format is fixed by kernel uapi (4-byte LE header, version 0x0002, 8-byte `{tag,perm,id}` entries) (R5-F27). No maintained Go library decodes it — `pkg/xattr` returns raw bytes, `joshlf/go-acl` has no push since 2020-04-11 and no releases (R5-F27). | If a maintained decoder appears with test-suite evidence, reconsider — the cost being replaced is only ~50 lines. |
| 5b | *(alternative)* shell out to `getfacl` | **REJECT** | UTILITY_MISSING on the target; a check that depends on it would report `unknown` on the machine that matters, which is exactly the under-claiming failure mode the contract forbids. | Never — even where `getfacl` exists, the syscall is cheaper and unbounded-exec-free. |
| 6 | **sshd_config parsing** | **BUILD**, narrow scope only | `golang.org/x/crypto/ssh` implements the protocol and configures a server programmatically; it has no config-file parser (R5-F40). `kevinburke/ssh_config` is a *client* parser whose own docs note `Match` is unsupported (R5-F41); pointing it at `sshd_config` would apply `Host`-block semantics to a `Match`-scoped file and produce confidently wrong findings. An ecosystem survey found no maintained server-side parser (R5-F42). | Negative claim from a non-exhaustive survey — re-verify once at implementation time before writing the parser. |
| 6b | *(alternative)* grep-style single-file scan | **REJECT** | `sshd_config(5)`: the **first** obtained value wins, `Include` files are glob-expanded in lexical order, and directives inside an unsatisfied `Match` block do not apply globally (R5-F43). Grep gets all three wrong. This is live on the target, not theoretical: the first line of the config is `Include /etc/ssh/sshd_config.d/*.conf` and the Latitude drop-in restates `PasswordAuthentication`. | Never. |
| 7 | **Bounded subprocess execution** | **BUILD** on stdlib `os/exec` + `syscall` | Everything needed is in stdlib: `Setpgid`, `Kill`, `SIGKILL` (R5-F15), `Cancel`, `WaitDelay` (R5-F12). The correctness is in *using* them right — the default `Cancel` kills only the leader (R5-F11) and `WaitDelay` alone leaves orphans behind (R5-F14). No library encodes that combination correctly for our safety rules. | None. |
| 8 | **CLI framework** | **REJECT (cobra / urfave / kong)** | Four extra modules including a YAML parser and a man-page generator for one subcommand (R5-F39); `flag.NewFlagSet` + a switch is ~20 lines (R5-F37). | A second and third subcommand with shared flag groups — still probably not. |
| 9 | **`golang.org/x/sys`** | **REJECT for this deliverable** | Every symbol needed exists in frozen stdlib `syscall` on linux/amd64 and was exercised in LOCAL_REPRO; the "syscall is deprecated" claim is a package NOTE, not a `Deprecated:` tag on any symbol (R5-F28, CONTESTED and resolved). | Needing `statx`, `openat2` flags, netlink, or a second GOOS — then x/sys is the one justified system dependency. |
| 10 | **`gopsutil` / `ghw` as libraries** | **REJECT** | Both ship ambient production root overrides (`HOST_PROC`/`HOST_SYS`, `GHW_CHROOT`) that let anything able to set an environment variable redirect every read a security sensor performs (R5-F5, R5-F7). Their *patterns* are worth stealing; their *code* is not worth the attack surface or the dependency weight for the ~15 values we need. | Never for this sensor. Fine for a non-security inventory tool. |
| 11 | **Deterministic JSON encoding** | **BUILD on stdlib `encoding/json` v1** | v1 sorts map keys and preserves struct declaration order (R5-F30); `SetEscapeHTML(false)` + `SetIndent` gives readable evidence (R5-F31). No canonical-JSON library needed. `encoding/json/v2` must be avoided: still `GOEXPERIMENT`-gated in Go 1.26 and marshals maps in *non-deterministic* order unless `Deterministic` is set (R5-F56). | v2 graduating with deterministic map order as the default. |
| 12 | **Golden-file test harness** (`goldie`, `cupaloy`) | **REJECT** | The `-update` flag idiom is ~10 lines of stdlib (R5-F47) and `testdata/` is already excluded from builds by the go tool (R5-F46). | None. |

**Net dependency count for the shipped binary: one** — `github.com/santhosh-tekuri/jsonschema/v6` (plus its single `golang.org/x/text`). Everything else is standard library.
