## Labelled assumptions R1 proceeded under

- **A-OR1** — Schema draft is UNKNOWN. R1 therefore recommends the only validator that covers draft-07, 2019-09 **and** 2020-12, so the decision is correct under all three outcomes. If OR1 returns draft-07, the recommendation does not change (santhosh v6 still wins on footprint); it only removes the default-draft hazard of R1-F31.
- **A-OR2** — DMI attribute modes on the Lava host match the kernel source (0400 for the four identity attributes, 0444 for the rest). The host snapshot already shows those four returning EACCES, which is consistent, so this assumption is well-supported but not independently reproduced.
- **A-OR3** — No POSIX ACL is assumed present on the target's sensitive paths; the sensor reads the xattr anyway and reports "no ACL present" as a positive observation rather than assuming it.
- **A-OR4** — Lockdown is assumed readable on the target (the snapshot proves the value was obtained); the generic branch for unreadable lockdown is written defensively from the WSL ENOENT reproduction.
- **A-OR5** — We assume we ship a prebuilt static binary AND vendor the (tiny) dependency set, so both outcomes are covered at negligible cost.
