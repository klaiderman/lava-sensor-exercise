**F10** | `Cmd.WaitDelay` bounds exactly those two failure modes: "If WaitDelay is non-zero, it bounds the time spent waiting on two sources of unexpected delay in Wait: a child process that fails to exit after the associated Context is canceled, and a child process that exits but leaves its I/O pipes unclosed." ## CONTRADICTIONS

**C6-1** — "gojsonschema is the standard Go JSON-Schema library" (widespread community claim, very high star count) **vs** its own README stating draft-07 is the ceiling and its dependencies frozen at 2018 pseudo-versions. **Resolution:** popularity is not draft coverage; the README is primary and authoritative about its own capability. Verdict REJECT unless the real schema is proven draft-07, and even then santhosh v6 wins on F3.

**C6-2** — "Just use `exec.CommandContext`, the context handles the timeout" (near-universal Go advice, and the first thing an LLM emits) **vs** the os/exec documentation's own statement that `WaitDelay` exists precisely because cancellation does NOT bound `Wait`. **Resolution:** the package documentation is primary and explicitly describes the failure mode; folklore loses. Both sides recorded deliberately, because the naive pattern is the default generated answer and the reviewer should see that we caught it.
