## D-02 Owner / host_id strategy
- `host_id`: keyed derivation (e.g. HMAC-SHA256 with a fixed sensor label) of `/etc/machine-id`, never the raw value (machine-id(5) confidentiality; F6, L32); `host_id_source` = `machine-id` and the caveat `stable across reboots; regenerated on re-image; clone-vulnerable`. Fallback chain: DMI `product_uuid` (EACCES here — record "denied", not "absent"; F3) -> machine-id -> hash of stable hardware ids (NVMe wwid/eui from sysfs or udev DB, permanent NIC MAC gated on addr_assign_type) -> explicit unknown. Never random, never time-based. Stability test: two consecutive runs on the host must agree (B1).
- `owner`: explicit unknown marker string plus `owner_candidates` (provider `Latitude.sh` from the cloud-init datasource class and the sshd drop-in name; facility `CHI`; host-key comment `root@259S052315` as image provenance) and the readable-but-placeholder asset tags reported as observed values (F5). Placeholder detection by pattern class (`To be filled by O.E.M.`, `Chassis Asset Tag`, `0123456789`, `Family`, empty), never literal match. Note the UNKNOWN is *by construction* on this host: every owner-bearing source is either root-only or a vendor placeholder.
- Numeric unknowns follow AM-5 (0 + a machine-level `unknowns` marker) — allowed because `additionalProperties` is open (F70).

## D-03 Effective sshd policy (C-03, resolved by host)
`sshd -G` is the primary oracle (works as uid 1000, 85 directives; F24). Own Include-aware walker is the fallback and the provenance source; disagreement = CONTESTED evidence. `-G -C` untested (F25): Match-conditional policy stays a bounded unknown. Listeners come from `/proc/net/tcp` + `systemctl show ssh.socket`, never from sshd_config (F30). Lead action: R3 L18 / R4 plan wording (PROPAGATION_AUDIT).

## D-04 Severity vs status (AM-4 / D6; C-36)
Recommendation: keep the contract's provisional rule — each check declares `impact`; reported `severity` = `impact` when status is `fail` **or** `unknown` (an unverifiable control is an assurance gap of the same weight), `info` when `pass`, and always `info` for observational checks. R5 adopted it (ARCHITECTURE_NOTES §4); no track contradicted it; SARIF's "default loud" principle (F66) supports not down-weighting unknowns. Engine-applied, never per check. Alternative considered: unknown -> one level lower than impact (argues unknown != confirmed failure) — rejected because it makes an EACCES-heavy unprivileged run look healthier than a privileged one.

## D-05 Dependencies (C-05, C-06)
Zero third-party runtime dependencies: stdlib `syscall` (not x/sys; F71), `os.Root` (not openat2; F19), `encoding/json` v1 (F72), `flag` (F74). `santhosh-tekuri/jsonschema/v6` v6.0.3 as a test-only import plus the release gate on the real `findings.json` (F69, F70). Runtime: stdlib invariant check mirroring the schema; on failure write the file anyway, exit 1, print the failing pointers — never suppress output (D3). Reversal conditions recorded per item in PRIOR_ART.

## D-06 Bounded execution and reads (settled by facts)
Single runner (Setpgid + group-kill Cancel + WaitDelay + capped writers + deferred Wait; F21-F23). One read primitive (O_NONBLOCK open, fstat-on-fd IsRegular, cap+1; F14-F16). os.Root for /sys and /proc with degradation (F19). Out-of-band deadline for the BMC sysfs read (F44, L40) — the healthy path is ~1-2 ms on this host, so a per-check budget in the low hundreds of ms is evidence-based; the whole-scan deadline never waits on a stuck goroutine (F17).

## D-07 No IPMI commands, ever (C-26: contract AM-6/C6a vs research)
Recommendation: supersede AM-6 — the sensor never opens `/dev/ipmi0` for commands and never executes `ipmitool`/Redfish requests; the sysfs identity path already proves "the BMC answered" (F44) with no hang or bus-disturbance risk (F45); `ipmitool` presence is inventory. Moot on this host (node not openable) but a real generic safety choice; matches CLAUDE.md "no BMC commands beyond read-only identification" if "identification" is read as the sysfs path.
