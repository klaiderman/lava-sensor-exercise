## Direction Lock (lead decisions — do not re-open)
- Deliverable: a Go module at `sensor/` producing one static binary `sensor` with the exact CLI `sensor scan --out findings.json` (plus `--version`; optional `--timeout <duration>` for the whole scan with a safe default). Exit 0 when the scan completed and wrote the file, even if findings fail/unknown; non-zero only if the output could not be written or the scan aborted. Logs to stderr only, never to the output file.
- Frozen architecture (LD-9 "Option 1.5", binding; details in `research/DECISIONS.md` and `CLAUDE.md`): module `sensor/` with `cmd/sensor/main.go` and exactly three internal packages —
  - `internal/probe`: typed `Observation{Source, Value, Status, Errno, ExitCode, Signal, Truncated, Bytes, Elapsed, LoadBearing}` with `ObsStatus ∈ {OK, EACCES, ENOENT, TIMEOUT, UTILITY_MISSING, UNSUPPORTED, EXEC_ERROR, CONTRADICTION}`; `classify(err) (ObsStatus, reason string)`; ONE bounded read primitive (`O_RDONLY|O_NONBLOCK|O_NOFOLLOW|O_CLOEXEC` where appropriate, fstat-on-fd `IsRegular` gate, cap from policy never `st_size`, cap+1 read to detect truncation) with an optional `*os.Root` for `/sys` and `/proc` (symlinks under /sys are legitimate; never follow into user-writable trees); ONE bounded exec runner (`exec.CommandContext` + `SysProcAttr{Setpgid: true}` + `Cancel` that kills the process group `syscall.Kill(-pid, SIGKILL)` + `WaitDelay` + capped stdout/stderr writers that kill on overflow + stdin `/dev/null` + minimal env `PATH`,`LC_ALL=C`); an out-of-band-deadline read (goroutine + timer, overrun ⇒ TIMEOUT, goroutine abandoned, scan never waits on it) used for the BMC sysfs attributes.
  - `internal/scan`: `Check` interface (`ID, Category, Title, Impact, Observational bool, Run(ctx, *Env) Result`), the explicit ordered roster (`checks.All()`, uniqueness of check_id asserted at startup), engine loop with per-check deadline and `recover()` (panic ⇒ `unknown`, reason "internal error", panic text in evidence), a shared read-once `Env` holding the three genuinely shared observations (`sshd -G` output, `/proc/self/mountinfo`, group database) plus a fixed clock and the `probe` handles, `finalize(result)` = (a) if any load-bearing observation is not OK and the check returned pass/fail ⇒ downgrade to `unknown` with a generated reason, (b) THEN severity rule LD-2, (c) evidence object generated from the `[]Observation` by one function (source/value/status/errno/exit code/timeout/truncation), deterministic writer (structs, sorted findings by category then check_id, UTC RFC 3339, `SetEscapeHTML(false)`), structural self-check mirroring the derived schema (required keys, enums, reason-when-fail/unknown, integer types, RFC 3339); on self-check failure still write the file, exit 1, print the failing pointers to stderr.
  - `internal/checks`: machine description collectors + the registered checks (content per `research/CHECK_REGISTRY.md`).
  - Not allowed: capability pre-phase, evidence store/key namespace, data-driven check table, plugins/`init()` self-registration, logger framework, flags beyond `--out` and `--version`, network I/O, third-party runtime imports (the ONLY third-party module is `github.com/santhosh-tekuri/jsonschema/v6` imported by `_test.go` files).
- Checks to implement: the 25 checks specified in `research/CHECK_REGISTRY.md` §2 (binding for ids, titles, impact, PASS/FAIL/UNKNOWN rules, evidence sources, fallbacks, traps, fixtures) plus ONE added by the lead: `BOOT_KERNEL_DRIFT` (BOOT_CHAIN, impact medium; FAIL when the running kernel `/proc/sys/kernel/osrelease` differs from the newest installed kernel found under `/boot/vmlinuz-*` or `/lib/modules/*`, PASS when equal, UNKNOWN when `/boot` is unreadable or no installed kernels are enumerable; evidence: running version, installed versions, `/boot` listing status, presence of `/var/run/reboot-required`). Build in two tiers so a budget cut still leaves ≥ 3 checks per category:
  - Tier 1 (first, in this order): `SSH_ROOT_LOGIN_POLICY` (the vertical slice), `SSH_AUTH_METHODS_POLICY`, `LOGIN_AND_ESCALATION_SURFACE`; `PRIVATE_KEY_MATERIAL_EXPOSURE`, `SYSTEM_SECRET_STORE_PROTECTION`, `PROVISIONING_DATA_PROTECTION`; `BMC_INBAND_INTERFACE_PRESENT`, `BMC_DEVICE_NODE_ACCESS`, `BMC_RESPONDS_IN_BAND`; `DISK_ENCRYPTION_AT_REST`, `UNUSED_ATTACHED_BLOCK_DEVICES`, `MEDIA_HEALTH_VISIBILITY`; `SECURE_BOOT_ENABLED`, `UEFI_PLATFORM_SETUP_MODE`, `UNSIGNED_OR_OUT_OF_TREE_MODULES`.
  - Tier 2: `SSH_POLICY_IN_FORCE`, `REMOTE_LISTENING_SURFACE`, `HOST_FIREWALL_STATE`; `CREDENTIAL_FILE_EXPOSURE`; `BMC_CLIENT_TOOLING_INVENTORY`, `BMC_HOST_INTERFACE_EXPOSURE`; `ROOT_FILESYSTEM_REDUNDANCY` (impact `low`, lead resolution of registry OPEN-4); `KERNEL_LOCKDOWN_MODE`, `TPM_PRESENCE`, `BOOT_ARTIFACT_READABILITY`, `BOOT_KERNEL_DRIFT`.
  - Lead resolutions of the registry's OPEN items: OPEN-1 keep forwarding/limits folded into `SSH_AUTH_METHODS_POLICY` evidence; OPEN-2 boot artifacts stay in BOOT_CHAIN; OPEN-3 resolved by adding `BOOT_KERNEL_DRIFT`; OPEN-4 impact low; OPEN-5/6 accepted (ACL readability and `sshd -G -C` settle at the first host run — the sensor must report the observed errno, never assume).
- Custom categories (LD-1, binding): `STORAGE_POSTURE` (data-at-rest / decommissioning hygiene: encryption at rest, redundancy of `/`, attached-but-unused devices never opened, drive health as a proved unknown, ext4 error counters) and `BOOT_CHAIN` (Secure Boot state, platform Setup Mode, kernel lockdown, unsigned/out-of-tree module taint, TPM presence, boot-artifact readability). Rationale goes to NOTES.md, not into code comments beyond one line each.
- Machine description strategy (LD-4 + `research/CHECK_REGISTRY.md` §1, binding): `host_id` = hex HMAC-SHA256(key = the literal label `lava-sensor-host-id`, message = trimmed `/etc/machine-id`), `host_id_source` = `machine-id (keyed hash)`; fallback chain product_uuid (EACCES ⇒ record denied, not absent) → machine-id → hash of stable hardware ids (NVMe eui/wwid from sysfs or `/run/udev/data`, permanent NIC MAC gated on `addr_assign_type`) → the literal `unknown`; never random or time-based. `owner` = `unknown` + `owner_candidates` (cloud-init datasource class / provider drop-in name, facility, image host-key comment) + observed DMI asset tags with placeholder-class detection (`To be filled by O.E.M.`, `Chassis Asset Tag`, `0123456789`, `Family`, empty). `vendor`/`model` from `/sys/class/dmi/id/{sys_vendor,product_name}` (board_* fallback). `os` from `/etc/os-release` (follow the symlink) + `/proc/sys/kernel/osrelease`. `cpu.model` from `/proc/cpuinfo`; `cpu.cores` = physical cores from `/sys/devices/system/cpu/cpu*/topology/{core_id,physical_package_id}` (fallback `/proc/cpuinfo` core id/physical id), extras `logical_cpus`, `sockets`, `threads_per_core`, `cores_basis`. `memory_bytes` = MemTotal kB × 1024 with `memory_source`. `storage[]` = `/sys/block/*` whole disks excluding loop/ram/zram/dm/md (report those separately as extras), `size_bytes` = sectors × 512, `model` from `device/model` or `/sys/class/nvme/<ctl>/model` or udev `ID_MODEL`, extras `transport`, `rotational`, `wwid`/`eui`, `partitions`, `holders`, `filesystem`. Unknown representation per AM-5: strings `unknown`; integers 0 only together with the machine-level `unknowns` object `{field: {reason, sources_tried}}`; every field has a `*_source`.
- Severity-vs-status rule (LD-2, central, enforced in `finalize()` after the load-bearing downgrade): reported `severity` = the check's declared `impact` when status is `fail` or `unknown`; `info` when status is `pass`; checks marked observational are always `info`. Never set per check by hand.
- Build: `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o bin/sensor ./cmd/sensor` from `sensor/`; Go 1.26; stdlib only unless `research/PRIOR_ART.md` marks a dependency REUSE (then pin it in go.mod with `go mod tidy` and vendor-free). The target host has no Go: the binary is cross-compiled locally; the source must still build with plain `go build`.
- Vertical slice FIRST: CLI → machine collection → ONE real check, `SSH_ROOT_LOGIN_POLICY` (it exercises the bounded exec runner via `sshd -G`, the bounded file reader via the Include-aware fallback parser, a real UNKNOWN path — `permitrootlogin without-password` + `/root/.ssh` EACCES must yield `unknown`, not `pass` — and the CONTESTED path when `sshd -G` and the parser disagree) → typed evidence → `finalize()` → findings.json → validate against `task/derived/finding.schema.json` in a test (jsonschema/v6, format assertion on). Stop, report the slice result, and only then expand to Tier 1 then Tier 2.
- Author ≠ reviewer: you never review your own work as "independent"; you write tests, you do not write the TEST_REPORT verdict.

## Invariant checklist (every item must be implemented AND covered by a test; the prompt-engineer maps each to prompt lines)
1. Read-only: no writes except the `--out` file; no temp files unless created under `os.TempDir()` and removed; no network sockets opened (no DNS, no HTTP); never invokes sudo/su/doas; never opens device nodes, FIFOs or sockets for reading (`Lstat`/`Stat` mode check first).
2. Bounded subprocesses: every exec uses a context deadline, runs in its own process group (`Setpgid`), is killed as a group on timeout (`Cancel` + `WaitDelay`), has stdout/stderr capped (bounded reader + kill on overflow), stdin from `/dev/null`, minimal environment (`PATH`, `LC_ALL=C`), and records exit code / signal / timeout / truncation in the evidence.
3. Bounded reads: file reads capped (e.g. 1 MiB default, per-source override), `/proc` and `/sys` reads via a bounded reader (sizes lie), directory walks bounded by depth, entry count, wall time and `xdev` (never cross mounts), prune `/proc`, `/sys`, `/dev`, `/run` in secret scans; symlinks resolved deliberately (allowed under `/sys`, not followed into other users' home directories).
4. Isolation: each check runs under `recover()`; a panic becomes an `unknown` finding with `reason` "internal error" + the panic string in evidence; a per-check deadline; the scan deadline; one check's failure never affects another's result or the output write.
5. No silent omission: every registered check emits exactly one finding per run; a check that cannot run (missing capability, EACCES, timeout, budget) emits `unknown` with `reason` and evidence of why; `check_id` uniqueness enforced at registration (fail fast) and tested.
6. Evidence semantics: EACCES ≠ absent; TIMEOUT ≠ false; missing utility ≠ missing capability (sysfs/procfs first, exec fallback); absence only from a successful listing; contradictions between observations recorded as such (not first-wins); under-claiming forbidden where a fallback exists.
7. No secret values: secret checks report path, type (by name/extension/permission and at most a bounded header sniff), mode, owner, size, mtime; never content, never partial key material, never environment variable values; a test greps the output for PEM headers, `sk-`, `AKIA`, JWT shapes, etc.
8. Unknown representation in `machine`: strings use the literal `unknown`; integers use 0 ONLY together with a machine-level `unknowns` object mapping the field to `{reason, sources_tried}`; never an empty string; every field carries provenance (`*_source`).
9. Determinism: stable key order (structs), findings sorted by category then check_id, no map iteration in output, times in UTC RFC 3339; two runs differ only in timestamps/volatile values (test with a fixed clock).
10. Schema: the output validates against `task/derived/finding.schema.json` in tests (the schema is embedded via `go:embed` for a self-check before writing, if PRIOR_ART approves a validator; otherwise tests validate with the chosen validator and the binary performs structural self-checks).
11. Portability: no hostname/vendor/customer string in any check's logic; capability probes gate branches; the same binary must produce a schema-valid, honest output on a machine without NVMe/IPMI/systemd/sshd (tested with the generic profile fixtures).
12. Testability without production overrides: filesystem root and command runner are injected internally (test-only seams, unexported); fixtures under `sensor/testdata/` (host-shaped profile A from the sanitized snapshot, generic profile B, restricted profile C with EACCES/missing tools); fault injection cases from `research/R3/FIXTURE_MATRIX.md`; golden files for findings.json shape.
13. Safety under root: if someone runs it as root it must still be read-only and bounded; no behaviour that mutates state becomes reachable.
14. Documentation: `sensor/README.md` with the exact one command to build and the exact one command to run, expected runtime, exit codes, and what UNKNOWN means; `reports/IMPLEMENTATION_NOTES.md` listing every check with its evidence sources and every place the implementation deviates from DECISIONS.md and why.
